# LeadForge 需求文档（Requirements）

> 版本：1.1 · 更新日期：2026-07-27 · 状态：基线

## 1. 背景与问题

独立开发者与小团队在「找商机 → 验证 → 选开源/创投对标 → 落地交付」链路中面临：

1. **热点噪声大**：平台热搜多为吃瓜新闻，难以直接变成可付费商机。
2. **验证成本高**：缺少统一工作流把红队、HITL、单位经济绑在同一条链路上。
3. **项目选型凭感觉**：GitHub/创投信息分散，缺少「可落地」过滤与落地方案。
4. **任务跟踪割裂**：方案生成后缺少本机可增删查改的落地任务中心。

## 2. 产品目标

构建 **LeadForge**：本机可运行的商业智能体工作台，覆盖：

**看热点 → 定商机 → 选项目 → 去落地**

默认垂直场景：本地到店获客落地页（Theme Pack 可插拔）。

## 3. 干系人

| 角色 | 诉求 |
|:---|:---|
| 独立开发者 / OPC | 两周内验证一个付费闭环 |
| 小团队增长负责人 | 从热搜/创投信号快速收敛到可执行任务 |
| 合规审校（HITL） | 广告法/红队门禁后再投放真钱 |

## 4. 功能需求

### 4.1 看热点（F-HOT）

| ID | 需求 | 优先级 |
|:---|:---|:---|
| F-HOT-01 | 多维通道：平台热搜 / 商机线索 / 创投 / 行业痛点 / AI 重构 | P0 |
| F-HOT-02 | 平台热搜按平台分页签，名次排序，支持行业筛选（未选=全网） | P0 |
| F-HOT-03 | 商机线索对齐 SeekMoney：痛点→根因→付费方→两周 MVP，禁止新闻套壳 | P0 |
| F-HOT-04 | 定时增量同步 36氪 / 创业邦 / 独立开发 / GitHub / newsnow | P1 |
| F-HOT-05 | AI 提炼可落地商机（SeekMoney + OPC 约束） | P1 |

### 4.2 定商机（F-OPP）

| ID | 需求 | 优先级 |
|:---|:---|:---|

| F-OPP-02 | 一键启动验证工作流，实时节点进度可见 | P0 |
| F-OPP-03 | 暂停 / 继续 / 停止 / 重新开始 | P0 |
| F-OPP-04 | 深度研判（宏观→痛点→重构→裁决）可选 | P1 |

|:---|:---|:---|

| F-PRJ-03 | 项目库筛选：来源/融资/性质等 | P1 |

### 4.4 去落地（F-LAND）

## 5. 非功能需求

| ID | 类别 | 要求 |
|:---|:---|:---|
| NFR-01 | 安全 | `.env` / `data/` / Token 不得入库；密钥仅本机配置 |
| NFR-02 | 可用性 | 无 Key 时可 MOCK_LLM 演示；正式模式禁止 mock 冒充真实推荐 |
| NFR-03 | 性能 | 热点库预热后列表秒级；验证全链路可接受 5–10 分钟 |
| NFR-04 | 可维护 | 模块边界清晰；Theme Pack / 规则 / skills 白名单外置 |
| NFR-05 | 合规 | 营销输出需经过红队与广告法规则门禁 |

## 6. 范围外（本期不做）

- 完整 TikHub UGC 评论爬取与 DBSCAN 聚类（SeekMoney 原项目能力，列为后续）
- 自动真实付费投放执行（仅到方案与 HITL）
- 多租户 SaaS 账号体系

## 7. 验收标准（摘要）

1. 本机 `start-local.bat` 可打开 `http://127.0.0.1:8080`。
2. 「商机线索」标题为「商机：行业 · 痛点」，非「围绕新闻」。
3. 「开始验证」自动打开工作流并显示进度。
4. 「去落地」可新建/搜索/编辑/删除任务与子任务。
5. `.env` 不出现在 Git 仓库中。
